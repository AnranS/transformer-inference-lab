## 任务 1：实现 `model.py`（70 分钟）

### 在 HF 源码里先看一遍

找 `LlamaModel.forward`，确认四件事的**顺序和位置**：

| 找什么 | 关键词 | 容易漏的点 |
|---|---|---|
| Embedding | `embed_tokens` | — |
| 层循环 | `for decoder_layer in self.layers` | 每层都要传 mask 和 `position_ids` |
| Final Norm | `self.norm(hidden_states)` | **在循环之后、LM Head 之前** |
| LM Head | `LlamaForCausalLM.lm_head` | 在 `LlamaForCausalLM` 里，不在 `LlamaModel` |

注意 HF 把模型拆成两层：`LlamaModel` 输出 hidden states，
`LlamaForCausalLM` 在外面套一个 `lm_head`。**我们合成一个类就行**，
但要知道这个分层，Day 19 复制权重时权重名会带 `model.` 前缀。

### 契约

- `__init__(config: ModelConfig)`
- `forward(input_ids, attention_mask=None, position_ids=None)` → `logits [B,S,V]`
- `position_ids` 为 `None` 时内部生成 `arange(S)`——**只在这一层允许**，
  因为顶层知道完整序列；`rope.py` 那一层依然禁止（Day 14 的决定）
- 层用 `nn.ModuleList`，不要用 Python list（否则参数不注册）
- `tie_word_embeddings=True` 时共享权重（复用 Day 3 的 `tie_weights` 逻辑）
- 保留 Day 3 的 `predict_next_token`，以及**只算最后一位**的 LM Head 路径

### 三个容易出错的地方

**1. 漏掉 final norm。** Pre-Norm 架构里最后一个 Block 的输出是
`x + f(Norm(x))`，这个 `x` 没有被归一化过。漏掉 final norm
不会报错，但和 HF 的 logits 永远对不上。Day 19 会立刻暴露它。

**2. `nn.ModuleList` vs list。** 用普通 list 装 Block，
`model.parameters()` 拿不到它们——优化器看不见、`state_dict` 里没有、
`.to(device)` 也不会搬。这是 PyTorch 新手最经典的坑。

**3. `position_ids` 的传递链。** `model → block → attention → rope`，
中间任何一层忘记透传，RoPE 就会拿到 `None`。
建议在 `rope.py` 里对 `position_ids is None` 直接抛异常（Day 14 的契约），
这样漏传会立刻炸，而不是静默用错位置。

## 任务 4：学习容差设计（30 分钟）

Day 5 学过默认容差，今天解决一个更难的问题：**多层网络的误差会累积，容差该怎么定？**

### 误差为什么累积

每一层的浮点运算都引入相对误差 `~eps`。`L` 层串起来，
最坏情况下误差按 `L` 线性增长，实际中因为随机抵消常常是 `sqrt(L)` 量级。
再加上 Attention 里的 softmax 和大规模求和会放大误差。

结论：**端到端 logits 的容差必须比单层宽**。用单层的容差去测最终输出，
会得到一堆假失败。

### 分层测试的策略（Day 19 的方法论）

不要一上来就测最终 logits。按这个顺序，**每级用各自的容差**：

| 级别 | 被测对象 | 期望误差量级 |
|---|---|---|
| 1 | RMSNorm | 接近 dtype eps |
| 2 | RoPE | 接近 dtype eps |
| 3 | Attention | 略大（softmax + 两次 GEMM） |
| 4 | MLP | 略大（三次 GEMM） |
| 5 | 单个 Block | 上面几项累积 |
| 6 | 最终 logits | 最宽 |

**分层的价值在定位。** 如果只测最终 logits，失败了你不知道是哪一层的问题；
分层测试会直接指出「Attention 那级就开始不对了」。

### 三条实践规则

**1. 正确性对齐一律用 fp32。** Day 5 的结论，重申一遍：
bf16 的 `rtol=1.6e-2` 太松，一个真有 bug 的实现也能通过。

**2. 先用默认容差，失败了再放宽——并记录为什么。**
不要一开始就写 `atol=1e-2` 图省事。每次放宽都要在注释里写清
「这一级涉及 N 次 GEMM + softmax，实测最大误差 X，取 3 倍余量」。

**3. 可以用 fp64 做参考实现。** 怀疑自己和 HF 都有精度损失时，
把同样的计算在 fp64 下跑一遍当作真值，分别比较——能判断出谁离真值更远。

在 `docs/concepts/05-numerical-tolerance.md` 里建一张表，Day 19～20 逐行填：

## 任务 5：搭 HF parity 脚手架（60 分钟）

今天**不做对齐**，只把架子搭好，明天（Day 19）才逐层对。

### 极小 HF 配置

```python
from transformers import LlamaConfig, LlamaForCausalLM

hf_config = LlamaConfig(
    vocab_size=256, hidden_size=128, intermediate_size=384,
    num_hidden_layers=2, num_attention_heads=4, num_key_value_heads=4,
    max_position_embeddings=128, rms_norm_eps=1e-6, rope_theta=10000.0,
    tie_word_embeddings=True,
    attn_implementation="eager",     # 关键：用朴素实现，便于逐层对照
)
hf_model = LlamaForCausalLM(hf_config).eval()
```

**`attn_implementation="eager"` 很重要**：默认可能走 SDPA 或 flash 后端，
数值上和你的朴素实现有细微差异，也不方便挂 hook 看中间结果。

`.eval()` 也别漏——虽然我们不用 dropout，但这是习惯。

### 取中间输出的方法

用 `register_forward_hook` 抓每个子模块的输出：

```python
captured = {}

def grab(name):
    def hook(module, args, output):
        captured[name] = output[0] if isinstance(output, tuple) else output
    return hook

hf_model.model.layers[0].input_layernorm.register_forward_hook(grab("hf_norm0"))
```

**注意 Attention 的输出是 tuple**（`(attn_output, attn_weights)` 之类），
所以上面要判断一下。这是挂 hook 最常踩的坑。

### 固定随机性

```python
torch.manual_seed(0)
```

而且要**同一份权重**——先建 HF 模型，再把权重复制到自研模型（Day 19 的活）。
不要各自随机初始化然后指望对齐。

## 今日最重要的面试式问题

**Pre-Norm 模型为什么在所有 Block 之后还需要一个 norm？**

因为 Pre-Norm 每层算的是 `x + f(Norm(x))`——归一化只作用在**分支**上，
残差主干上的 `x` 一路没被归一化过。经过 `L` 层累加，主干的数值量级会持续增长。
最后必须补一个 `final_norm` 才能把量级拉回来交给 LM Head。

Post-Norm 不需要，因为它每层结尾都归一化了。

追问：**为什么端到端 logits 的对齐容差要比单层宽？**

浮点误差逐层累积。每层引入约 `eps` 的相对误差，`L` 层后是 `sqrt(L)` 到 `L` 倍，
Attention 里的 softmax 和大规模求和还会额外放大。用单层容差测最终输出会得到假失败。

正确做法是**分层测试、逐级放宽**——而且这样失败时能直接定位到哪一层出问题，
比只测最终 logits 有用得多。
