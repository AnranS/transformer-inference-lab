## 任务 1：学习 SDPA 的每个参数（25 分钟）

```python
F.scaled_dot_product_attention(
    query, key, value,
    attn_mask=None, dropout_p=0.0, is_causal=False, scale=None, enable_gqa=False,
)
```

逐个搞清，**每个参数后面都对应一个具体的坑**：

| 参数 | 含义 | 坑 |
|---|---|---|
| `attn_mask` | bool 掩码或 additive 掩码 | bool 里 **`True` = 参与计算**，和「mask 掉」的直觉相反 |
| `is_causal` | 内部生成因果掩码 | **不能和 `attn_mask` 同时给**；且它按 `Sq × Skv` 右下角对齐，Decode 时行为要验证 |
| `scale` | 缩放系数 | 默认 `1/sqrt(query.size(-1))`，即 `1/sqrt(Dh)`。传错等于 Day 6 说的那个 bug |
| `dropout_p` | 注意力 dropout | **推理必须为 0**。留着非 0 会让输出每次都不同 |
| `enable_gqa` | 允许 `Hkv < Hq` | Day 31 才用，今天设 `False`，先自己写 `repeat_kv` |

`is_causal` 和 `attn_mask` 互斥这一点要记牢：等到 Day 23 要同时处理
**因果 + padding** 时，就不能用 `is_causal` 了，必须自己合成一个掩码传 `attn_mask`。

## 任务 2：实现 `naive_attention`（50 分钟）

在 `src/mini_transformer/attention.py` 里写，五步照 Day 6 的公式：

```text
1. scores = Q @ K.transpose(-2, -1)      # [B, Hq, Sq, Skv]
2. scores = scores / sqrt(Dh)
3. scores = scores + mask                # additive；或 masked_fill
4. probs  = scores.softmax(dim=-1)       # 沿 Skv，不是 Sq
5. out    = probs @ V                    # [B, Hq, Sq, Dh]
```

契约（沿用 Day 01～04 的习惯，错误信息带实际形状）：

- Q/K/V 都是四维 `[B, H, S, Dh]`，否则 `ValueError`
- `Q.shape[-1] == K.shape[-1]`，否则 `ValueError`
- `K.shape[-2] == V.shape[-2]`（Skv 必须一致），否则 `ValueError`
- 允许 `Sq != Skv`——**这不是错误**，Decode 阶段就是 `Sq=1, Skv=S+1`

第 4 步的 `dim=-1` 是今天最容易写错的一个字符。想清楚：
softmax 要让「当前 query 对所有 key 的注意力权重之和为 1」，
所以归一化必须沿 **key 维**，也就是最后一维。写成 `dim=-2` 代码照样跑，结果全错。

## 任务 4：学习四种 mask 的组合（25 分钟）

Mask 有**两个正交维度**，四种组合都要能认出来：

|  | **Boolean** | **Additive** |
|---|---|---|
| **Causal**（禁止看未来） | `tril` 布尔下三角，`True`=可见 | 上三角填 `-inf`，下三角填 `0` |
| **Padding**（忽略补齐位） | `attention_mask == 1` | PAD 位填 `-inf` |

两个维度的区别：

- **来源不同**：causal 由**任务性质**决定（因果语言模型不能看未来），
  padding 由**批处理**决定（不同长度凑一个 batch）。前者恒定，后者随输入变。
- **形式不同**：additive 直接加到 scores 上；boolean 要走 `masked_fill`。
  SDPA 两种都收，但**语义相反**——bool 的 `True` 是「保留」，additive 的非 0 是「屏蔽」。

**形状怎么对齐**（Day 5 广播陷阱二的正式版）：

```text
scores        [B, Hq, Sq, Skv]
causal mask   [Sq, Skv]        → 广播到 [1, 1, Sq, Skv]
padding mask  [B, Skv]         → 必须 view 成 [B, 1, 1, Skv]
两者相加      → [B, 1, Sq, Skv] → 广播到 [B, Hq, Sq, Skv]
```

padding mask 那一步**必须手写 `view`**，靠广播猜一定错。

### 两个必须知道的陷阱

**陷阱一：`-inf` 会产生 NaN。** 如果某一行**全部**被屏蔽（一条序列整个是 PAD），
`softmax([-inf, -inf, ...])` 是 `0/0` = NaN，而且 NaN 会污染后面所有计算。
处理方式：要么保证每行至少一个可见位，要么屏蔽后再把 NaN 置零。

**陷阱二：fp16 下不能用 `-1e9`。** fp16 最大值约 65504，`-1e9` 直接溢出成 `-inf`
（这次侥幸对了），但 `-1e9` 在 bf16 / fp16 的中间运算里可能变成 NaN。
正确写法是 `torch.finfo(dtype).min`，跟着 dtype 走。

## 任务 5：实现 causal mask 与 padding mask（50 分钟）

写两个独立的构造函数，再写一个合成函数。**分开写是为了能分开测。**

```text
build_causal_mask(Sq, Skv, device, dtype)   -> [Sq, Skv]
build_padding_mask(attention_mask, dtype)   -> [B, 1, 1, Skv]
combine(causal, padding)                    -> [B, 1, Sq, Skv]
```

三个函数统一返回或合成 **additive mask**：可见位置为 `0`，屏蔽位置为
`torch.finfo(dtype).min`。完整接口契约和逐步 TDD 顺序见
[`concepts/06-masks.md`](./concepts/06-masks.md)。

构造函数完成后，还要为 `naive_attention` 增加可选的 `attention_bias` 参数，并严格放在：

```text
QKᵀ → / sqrt(Dh) → + attention_bias → softmax → @V
```

若只构造 mask 却不接入 softmax 前的 scores，padding 和 causal 都不会真正生效。

### `Sq != Skv` 时怎么办（今天最关键的一点）

Prefill 时 `Sq == Skv == S`，`tril` 就对了。但 Decode 时 `Sq=1`、`Skv=S+1`：

```text
只有一个 query（最新那个 token），它可以看见全部 S+1 个 key
→ mask 应该是全 True 的一行 [1, S+1]
→ 而不是 tril(1, S+1) 那样只看见第 0 个 key
```

**写 `tril(torch.ones(Sq, Skv))` 会在 Decode 时把注意力打回起点，是本路线最著名的 bug。**
正确做法是让因果关系按**绝对位置**判断：

```text
query 的绝对位置 = Skv - Sq + i        (i 从 0 到 Sq-1)
key   的绝对位置 = j                   (j 从 0 到 Skv-1)
可见条件：j <= Skv - Sq + i
```

即掩码按**右下角对齐**，不是左上角。今天就把它写对并测出来——
这条属于 KV Cache 阶段的「必须排查的错误」，但现在写对能省掉后面几小时的调试。

## 今日最重要的面试式问题

**causal mask 与 padding mask 有什么区别？**

来源不同：causal 由任务性质决定（不能看未来），对任何输入都一样；
padding 由批处理决定（长度不齐），随输入变化。
作用维度也不同：causal 约束 `(Sq, Skv)` 这一对，padding 只约束 `Skv`（以及 batch）。
两者必须**同时**生效，所以要合成一个掩码。

追问：**Decode 阶段 `Sq=1`、`Skv=100`，causal mask 长什么样？**

**全部可见的一行。** 这个唯一的 query 是最新 token，它能看到全部 100 个历史 key。
写成 `tril(1, 100)` 会让它只看见第 0 个 key——这是 KV Cache 阶段最经典的 bug。
