## 任务 1：学习 RMSNorm（25 分钟）

### 公式与差异

```text
LayerNorm:  y = (x - mean(x)) / sqrt(var(x) + eps) · weight + bias
RMSNorm:    y =  x            / sqrt(mean(x²) + eps) · weight
```

RMSNorm 比 LayerNorm **少了两样东西**：

1. **减均值**（re-centering）——不再把分布中心移到 0
2. **bias**——只有缩放，没有平移

论文的发现是：LayerNorm 的效果主要来自**重新缩放**，重新中心化贡献很小。
去掉之后省一次求均值和一次减法，且少一组参数，效果基本不变。

参数量：RMSNorm 只有 `weight`，形状 `[D]`。一个 32 层模型的全部 norm 参数
是 `2 × 32 × D`——在 8B 模型里约 0.26M，**占比不到万分之四**，可以忽略。

### 归一化沿哪一维

**沿 hidden dimension，即最后一维。** 对 `[B, S, D]` 输入：

```python
variance = x.pow(2).mean(dim=-1, keepdim=True)   # [B, S, 1]
```

每个 token 独立归一化，`B` 和 `S` 都不参与统计。这一点很重要：
**RMSNorm 不跨 token 混合信息**，所以它对 batch 组成、padding、KV Cache 都完全透明。
（对比 BatchNorm 跨 batch 统计，那在推理里是灾难。）

### 两个数值细节

**细节一：`eps` 在 `sqrt` 内部。**

```python
x * torch.rsqrt(variance + eps)      # 对
x / (torch.sqrt(variance) + eps)     # 错，量级完全不同
```

**细节二：中间统计必须转 fp32。** Llama 的实现是这样：

```python
input_dtype = x.dtype
x = x.to(torch.float32)                       # 升到 fp32
variance = x.pow(2).mean(-1, keepdim=True)
x = x * torch.rsqrt(variance + self.eps)
return self.weight * x.to(input_dtype)        # 先降回原 dtype，再乘 weight
```

为什么必须升 fp32：`x.pow(2)` 会把量级**平方**。bf16 的动态范围虽大，
但只有 8 位尾数，求和 `D` 项（`D=4096`）后精度损失明显；fp16 更糟——
`x` 稍大就直接溢出成 `inf`。

注意最后一行的顺序：**先 `.to(input_dtype)` 再乘 `weight`**。
这不是随意写的——HF 就是这个顺序，Day 19 做逐层 parity 时，
顺序不同会产生可观测的数值差异。

## 任务 2：实现并与 `torch.nn.RMSNorm` 对齐（50 分钟）

契约：

- `__init__(hidden_size, eps=1e-6)`
- `weight` 初始化为**全 1**（不是随机！否则第一次前向就把信号缩放乱了）
- `forward`：`[..., D]` → `[..., D]`，形状不变
- 最后一维不等于 `hidden_size` → `ValueError`
- 中间统计走 fp32，输出 dtype 与输入一致

对齐测试：

```python
mine = MyRMSNorm(D)
ref  = torch.nn.RMSNorm(D, eps=mine.eps)
ref.weight.data.copy_(mine.weight.data)
torch.testing.assert_close(mine(x), ref(x))
```

> `torch.nn.RMSNorm` 需要 PyTorch 2.4+。版本不够的话用 `F.rms_norm`，
> 或者手写一个 fp64 参考实现来对齐（fp64 参考也是个好习惯，Day 18 会正式用到）。

`eps` 默认值要注意：PyTorch 默认是 `None`（退化为 dtype 的 eps），
而 **Llama 用 `1e-6`**（`rms_norm_eps`）。我们跟 Llama，Day 16 把它放进 config。

## 任务 3：学习 SwiGLU（30 分钟）

### 公式

```text
gate = SiLU(x @ Wgate)        SiLU(z) = z · sigmoid(z)
up   =      x @ Wup
out  = (gate ⊙ up) @ Wdown    ⊙ 是逐元素乘
```

三个投影，形状（按 `nn.Linear(in, out).weight` 是 `[out, in]` 的约定）：

| 投影 | `nn.Linear` | `weight` 形状 |
|---|---|---|
| `gate_proj` | `nn.Linear(D, I, bias=False)` | `[I, D]` |
| `up_proj` | `nn.Linear(D, I, bias=False)` | `[I, D]` |
| `down_proj` | `nn.Linear(I, D, bias=False)` | `[D, I]` |

`I` 是 `intermediate_size`。

### 为什么是三个投影（关键洞察）

普通 Transformer 的 FFN 只有两个投影：`D → 4D → D`。SwiGLU 有三个，
看起来参数多了 50%。但实际模型里 `I` 不取 `4D`，而是取约 `8/3 · D`：

```text
普通 FFN   W1[D,4D] + W2[4D,D]           = 8D²
SwiGLU     3 × [D, 8/3·D]                = 8D²      ← 一样
```

**用同样的参数预算，换来了一个门控机制。** `gate` 经过 SiLU 后作为软开关，
逐元素决定 `up` 的哪些通道能通过。这就是 GLU 系列的价值。

真实模型的比例：

| 模型 | `D` | `I` | `I/D` |
|---|---|---|---|
| Llama-2 7B | 4096 | 11008 | 2.688（≈ 8/3） |
| Llama-3 8B | 4096 | 14336 | 3.500 |

Llama-2 贴着 `8/3 = 2.667`（`8/3 × 4096 = 10923`，向上取到 256 的倍数得 11008）。
Llama-3 8B 明显放宽到 3.5——**这条经验规则不是硬约束**，只是个常见起点。
所以 `intermediate_size` 必须从 config 读，不能由 `hidden_size` 算出来。

### 为什么用 SiLU 而不是 ReLU

SiLU（也叫 Swish）`z · sigmoid(z)` 是**平滑**的，且在负半轴有小幅非零输出。
ReLU 在 0 处不可导、负半轴全为 0（会产生「死神经元」）。
对门控来说平滑很重要——硬截断会让门要么全开要么全关。

## 任务 4：实现 MLP（55 分钟）

契约：

- `__init__(hidden_size, intermediate_size, *, bias=False)`
- 三个 `nn.Linear`，命名跟 HF 一致：`gate_proj` / `up_proj` / `down_proj`
  （**Day 19 复制权重时会按名字对应，现在起名对了能省事**）
- `forward`：`[B, S, D]` → `[B, S, D]`
- `bias=False` 对齐 Llama

实现只有一行核心逻辑，但**别写成一行**——分开写便于打断点看中间形状：

```python
gate = F.silu(self.gate_proj(x))     # [B, S, I]
up   = self.up_proj(x)               # [B, S, I]
return self.down_proj(gate * up)     # [B, S, D]
```

## 任务 5：记录 shape、参数量、FLOPs（30 分钟）

Notion 明确要求记录这三项。写进 `docs/concepts/09-swiglu.md`：

**参数量**：`3 × D × I`

**每 token 的 FLOPs**：三次矩阵乘，各 `2 × D × I`（乘加算 2 FLOP），合计 `6 × D × I`。

在 Llama-3 8B 上代入 `D=4096, I=14336`：

```text
单层 MLP 参数  = 3 × 4096 × 14336 = 176.2M
单层 MLP FLOPs = 6 × 4096 × 14336 = 352.3 MFLOP / token
```

和 Attention 对比（`Hq=32, Hkv=8, Dh=128`）：

```text
单层 Attention 参数 = 2 × D × Dh × (Hq + Hkv) = 41.9M
单层 MLP       参数 = 176.2M                    ← 是 Attention 的 4.2 倍
```

**这个比例值得记住**：现代 LLM 的参数大头在 MLP，不在 Attention。
但 Attention 的**显存**大头（KV Cache + `S²` 中间矩阵）远超 MLP。
参数量和显存占用是两回事，第 4 周做 profile 时会反复用到这个区分。

## 任务 6：单元测试（50 分钟）

`tests/test_norm.py`：

1. 形状不变：`[B,S,D]` → `[B,S,D]`
2. 与 `torch.nn.RMSNorm`（同 weight、同 eps）对齐
3. `weight` 初始值全为 1
4. 输入放大 100 倍，输出**几乎不变**（归一化的本质；用宽容差）
5. bf16 输入时输出 dtype 是 bf16，但内部统计走 fp32
   （对比「全程 bf16」的实现，误差应更小）
6. 最后一维不匹配时报错
7. 不含 bias（`hasattr(m, "bias") is False` 或 `m.bias is None`）

第 4 条是 RMSNorm 语义最直接的断言，**比对齐测试更能说明它在做什么**。

`tests/test_mlp.py`：

1. 形状：`[B,S,D]` → `[B,S,D]`
2. 参数量等于 `3 × D × I`
3. 三个投影都不带 bias
4. `gate` 全为 0 时输出为 0（门控语义：门关了就什么都不通过）
5. 与手写的 `down(silu(gate(x)) * up(x))` 逐元素一致（防止把 SiLU 加到 `up` 上）

第 5 条防的是一个真实的高频错误：**SiLU 只作用在 `gate` 上，不作用在 `up` 上**。
写反了形状完全正确、也不报错。

## 今日最重要的面试式问题

**RMSNorm 与 LayerNorm 相比少了什么，为什么可以少？**

少了**减均值**和**bias**。RMSNorm 论文发现 LayerNorm 的收益主要来自重新缩放
（除以标准差），重新中心化贡献很小。去掉后省一次均值计算和一组参数，效果基本不变。

追问：**为什么 RMSNorm 的中间统计要转 fp32？**

因为 `x²` 会把量级平方，再对 `D`（几千）项求和。bf16 只有 8 位尾数，
累加误差显著；fp16 动态范围小，`x` 稍大就溢出成 `inf`。
转 fp32 算完统计、再降回原 dtype，是精度和显存的折中。

再追问：**归一化沿最后一维，对推理有什么好处？**

每个 token 独立归一化，**不跨 token 混合信息**。所以它对 batch 里有多少条序列、
有没有 padding、KV Cache 里存了多少历史，全都无感——可以放心在任意
`[*, D]` 形状上调用。如果换成 BatchNorm 那种跨样本统计，推理时 batch 组成变化
就会改变单条序列的输出，这在服务里是不可接受的。
