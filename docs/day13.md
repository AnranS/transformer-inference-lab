## 任务 1：读 RoFormer 论文（60 分钟）

### 先搞清它要解决什么问题

回到 Day 5 的缺口：Token Embedding 查不出位置。补位置信息有三条路：

| 方案 | 做法 | 问题 |
|---|---|---|
| 可学习绝对位置（GPT-2） | 加一张 `[max_S, D]` 的位置表 | 超出 `max_S` 就没法用，外推能力差 |
| 正弦绝对位置（原论文 3.5） | 用固定的 sin/cos 函数生成 | 加在 embedding 上，位置信息会被后续层稀释 |
| **RoPE** | **旋转 Q/K 向量** | 相对位置天然编码，外推较好 |

RoPE 的核心思路和前两者有本质区别：**它不是「加」位置，而是「转」向量。**

前两者是 `x = x + pos_emb`，位置信息混进了 hidden state；
RoPE 是在 Attention 内部对 Q/K 做旋转，**hidden state 本身不带位置**。

### 核心机制

把 `Dh` 维向量看成 `Dh/2` 个二维平面上的点。对位置 `m` 的向量，
第 `i` 个平面旋转 `m · θ_i` 弧度：

```text
[x'_{2i}  ]   [cos(mθ_i)  -sin(mθ_i)] [x_{2i}  ]
[x'_{2i+1}] = [sin(mθ_i)   cos(mθ_i)] [x_{2i+1}]
```

频率随维度指数衰减：

```text
θ_i = base^(-2i/Dh)        base = 10000（Llama 的 rope_theta）
```

`Dh=8` 时 `θ` 依次是 `[1.0, 0.1, 0.01, 0.001]`——
**低维平面转得快（捕捉近距离），高维平面转得慢（捕捉远距离）**。
最慢那个平面的周期是 `2π/0.001 ≈ 6283` 个位置，
所以它在几千 token 的范围内都还没转完一圈，能表达很长的距离差。

> `rope_theta` 就是这个 `base`。长上下文模型常把它从 10000 调大到 500000
> （Llama-3 就是），效果是把所有频率整体调慢，从而覆盖更长的距离。
> 这是「RoPE 外推」的最简单做法，Day 16 会把它放进 config。

### 三条必须记住的性质

**1. RoPE 只作用在 Q 和 K，不作用在 V。**

原因：位置信息的作用是影响「谁该注意谁」，也就是 `QKᵀ` 这个**打分**过程。
`V` 是被聚合的**内容**，不需要带位置。给 `V` 也转会破坏内容本身。

**2. 旋转不改变向量长度。**

旋转矩阵是正交的，`|R_m q| = |q|`。所以 RoPE **不会改变 Q/K 的量级**，
也就不影响 `sqrt(Dh)` 的缩放假设。这是它比「加位置」更干净的地方。

**3. 相对位置性质（今天的核心）。**

```text
<R_m q, R_n k> = <q, R_{n-m} k>
```

两个旋转后向量的内积，**只依赖 `n - m`，与 `m`、`n` 各自的绝对值无关**。
这意味着 attention 分数天然只看相对距离。

## 任务 2：手算 2 维旋转与相对位置性质（70 分钟）

### 第一步：单个旋转

取 `Dh = 2`（只有一个平面）、`θ = 1`、`q = [1, 0]`，算位置 `m=1` 的旋转结果：

```text
R_1 q = [cos(1), sin(1)] = [0.5403, 0.8415]
```

再算 `m=2`、`m=3`，观察向量在单位圆上转动。**画出来**，别只算数。

### 第二步：验证相对位置性质（重点）

`q = k = [1, 0]`，`θ = 1`。取三组位置，算 `<R_m q, R_n k>`：

| `m` | `n` | `n - m` | `<R_m q, R_n k>` | `cos(n-m)` |
|---|---|---|---|---|
| 2 | 5 | 3 | ? | ? |
| 7 | 10 | 3 | ? | ? |
| 0 | 3 | 3 | ? | ? |

自己算完再核对——这三组答案我验证过，**全部等于 `cos(3) = -0.98999`**：

```text
m=2  n=5   → -0.98999
m=7  n=10  → -0.98999
m=0  n=3   → -0.98999
```

绝对位置从 0 到 10 变了三轮，只要 `n-m=3` 不变，内积就完全不变。
**这就是 RoPE 的全部魔法。**

### 第三步：自己推一遍为什么

用二维的情况推。`q = [q_1, q_2]`、`k = [k_1, k_2]`：

```text
R_m q = [q_1 cos mθ - q_2 sin mθ,  q_1 sin mθ + q_2 cos mθ]
R_n k = [k_1 cos nθ - k_2 sin nθ,  k_1 sin nθ + k_2 cos nθ]
```

把内积展开，用积化和差合并，会发现所有 `mθ` 和 `nθ` 都以 `(n-m)θ` 的形式出现。
**动手推一遍，不要只看结论**——这是今天 70 分钟的主要价值所在。

用复数表示会快得多：把 `[q_1, q_2]` 看成 `q_1 + i q_2`，旋转就是乘 `e^{imθ}`，
内积的实部是 `Re[(q e^{imθ})* · (k e^{inθ})] = Re[q* k e^{i(n-m)θ}]`。
一眼就能看出只依赖 `n-m`。

### 第四步：想清楚这对 Decode 意味着什么

这是明天写代码、以及 Day 26～30 调 KV Cache 的关键。

> 生成第 101 个 token 时，它的绝对位置是 100。
> 如果你在 Decode 时给它传 `position_ids = 0`（因为输入只有 1 个 token，
> 下标从 0 开始），会发生什么？

答案：`R_0` 是恒等变换，这个 token 会被当成句子的**第一个**词。
它和历史 key 的相对距离全部错位，注意力彻底乱掉。

**Decode 必须传正确的绝对位置**，也就是 `cache_position`。
「RoPE position 从 0 重新开始」是 KV Cache 阶段「必须排查的错误」的第一条，
就是这个。今天先在笔记里写死这条结论。

## 今日最重要的面试式问题

**RoPE 为什么只应用到 Q 和 K？**

位置信息的作用是影响**注意力打分**，也就是 `QKᵀ`。
`V` 承载的是被聚合的**内容**，不参与打分，加位置只会污染内容。

追问：**RoPE 凭什么能表达相对位置？**

因为 `<R_m q, R_n k> = <q, R_{n-m} k>`。旋转矩阵的正交性让两次旋转的内积
只留下角度差 `(n-m)θ`，绝对位置在内积里消掉了。所以注意力分数天然只看相对距离。

再追问：**Decode 时只输入一个 token，`position_ids` 该传什么？**

传它的**绝对位置**，即已缓存的长度（`cache_position`），**不是 0**。
传 0 会让 `R_0` 变成恒等变换，模型把这个 token 当成句首，
和所有历史 key 的相对距离全部错位。
